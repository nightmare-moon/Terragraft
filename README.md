# Terragraft v1.0 — Single-install Windows Terraform Project Console

> GitHub publishing: see [GITHUB_PUBLISH.md](GITHUB_PUBLISH.md). Do not commit the generated `.env` or state files.


**One installation. Unlimited separately managed Terraform projects. No per-project server installation, no upgrade or state migration.**

Terragraft is a local Windows/Docker lab for organizing NEW Terraform/OpenTofu projects. PostgreSQL stores each project's remote Terraform state. A Windows runner performs queued plans, and requires human approval before applying a saved plan. It does **not** enable concurrent applies within a single Terraform state.

## Requirements

- Windows 11 / Windows PowerShell 5.1+ (PowerShell 7 also works for most scripts)
- Docker Desktop (Linux containers), running
- Python 3 on PATH (the Windows runner needs only Python standard library)
- Terraform CLI (`terraform`) or OpenTofu CLI (`tofu`) on PATH
- Port **8080** available on localhost

### 1. Fresh install — one time

Unzip **Terragraft_One_Install_Windows.zip** to the folder where you want the central server to live, e.g. `D:\Tools\Terragraft`. Keep that folder in place. In PowerShell, change to it:

```powershell
cd D:\Tools\Terragraft
.\INSTALL.ps1 -ProjectsRoot "D:\TerraformProjects"
```

Alternatively, double-click `INSTALL.cmd` to use `D:\TerraformProjects` by default when D: exists (otherwise `%USERPROFILE%\TerraformProjects`).

The installer automatically:
1. Creates the projects-root folder if needed.
2. Generates fresh local `.env` secrets, **only if it does not already exist**.
3. Saves the root/runner configuration in `.terragraft.local.json`.
4. Builds and starts PostgreSQL and Terragraft API containers in a **new Compose project named `terragraft`** (separate from earlier `terragraft-lab`).
5. Starts a Windows runner in another PowerShell window, and opens the browser console.

Open **http://127.0.0.1:8080/console**. In another PowerShell, run `.\COPY-ADMIN-TOKEN.ps1` to copy the admin token to the clipboard, then paste into the console and press **Connect**. Do not share this token.

### 2. Connect a NEW Terraform project — one command per project

**Use this command from the central Terragraft installation directory, not from the Terraform project directory.** It creates `backend.tf` with the correct workspace URL (no secrets in the file) and registers the project with the central console. It refuses to overwrite existing backends or migrate existing state.

For a project with an existing `main.tf` but **no Terraform state**:

```powershell
.\CONNECT-PROJECT.ps1 -Path "D:\TerraformProjects\Network" -Workspace "network-dev" -Name "Network"
```

For a completely NEW demonstration directory (creates `main.tf` with a safe `terraform_data` resource):

```powershell
.\CONNECT-PROJECT.ps1 -Path "D:\TerraformProjects\Demo" -Workspace "demo" -Create
```

For another independent project:

```powershell
.\CONNECT-PROJECT.ps1 -Path "D:\TerraformProjects\Apps" -Workspace "apps-dev" -Name "Applications"
```

All project paths **must live beneath** the projects root chosen during installation. If you prefer a different root, set it at initial install; the Windows runner will not execute Terraform outside that root. Do not register untrusted HCL configurations or provider/provisioner code.

The workspace name must be distinct for **each independent state**. All engineers or workers managing the same infrastructure stack should share the **same** backend workspace; standard Terraform will serialize their applies with whole-state locking.

### 3. Manage projects through the console

1. Leave the **Windows runner window** open (it polls the server and executes queued work).
2. Open http://127.0.0.1:8080/console and click **Connect** using your admin token.
3. Choose **Queue plan** beside a registered project.
4. The Windows runner executes `terraform init` / `terraform plan -out=<saved plan>`.
5. Open **Show Terraform output** and review it. If changes exist, approve by typing the exact workspace name. The runner applies **the saved plan**; it will not silently run an unapproved fresh apply.
6. Click **Explore graph** for state resources and dependency relationships.

The API and PostgreSQL can run even when the runner is closed, but queued jobs won't execute until you start the runner. After reboot:

```powershell
.\RUN.ps1
```

To stop containers (keeps data, .env and project registrations):

```powershell
.\STOP.ps1
```

Stop the separate runner window with `Ctrl+C`.

### 4. Prefer normal Terraform CLI commands?

From any PowerShell session, load your backend password from the central installation (dot-source once):

```powershell
. "D:\Tools\Terragraft\USE-TERRAGRAFT.ps1"
cd D:\TerraformProjects\Network
terraform init
terraform plan
terraform apply
```

Every project has its own `backend.tf`, generated by `CONNECT-PROJECT.ps1`, so no `-backend-config` flags are needed. Do not commit credentials to HCL. **Use either the console approval workflow or manual CLI**, and avoid running manual CLI operations while a dashboard run for the same workspace is in progress.

### Other scripts

| Script | Purpose |
|---|---|
| `INSTALL.ps1` or `INSTALL.cmd` | One-time fresh installation; does not migrate prior state |
| `RUN.ps1` / `RUN.cmd` | Start existing server plus host runner and open dashboard |
| `CONNECT-PROJECT.ps1` | Add one NEW Terraform project to the existing central server |
| `COPY-ADMIN-TOKEN.ps1` | Place the admin token on the local clipboard for dashboard login |
| `USE-TERRAGRAFT.ps1` | Load Terraform HTTP backend password into current PowerShell session |
| `RUNNER.ps1` | Start the Windows runner manually if you closed its window |
| `STOP.ps1` | Stop Docker stack without deleting state |
| `RESET-OLD-LAB.ps1` | **Optional:** stop the prior v0.2/v0.3 `terragraft-lab` stack if it still uses port 8080 |
| `RESET-OLD-LAB.ps1 -DeleteOldData` | **Irreversible:** asks for explicit typed confirmation before removing only the old lab's Docker volume |

### Verify

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
# expected: status = ok, version = 1.0.0
docker compose -p terragraft ps
```

### Important boundaries

- **Local-only by default.** Port 8080 listens on `127.0.0.1`; Docker does not publish the PostgreSQL port. This package isn't a drop-in multi-computer team service.
- **Whole-state locking persists.** Graph leases and transactions are experimental metadata operations only, not independent concurrent Terraform applies within one state.
- **No state migration.** Use only brand-new projects or existing HCL configurations with **no** state/backend. Move existing states with Terraform's supported procedures separately after backup.
- Do not upload `.env`, saved `.tfplan` files, state, backups or credentials to repositories. State can contain secrets; project and plan output may as well.
- Running Terraform is a trusted-code action. For work outside a lab, review provider binaries, HCL, credentials, runner authentication, TLS, backups, and access policies before production deployment.
- Docker/Terraform end-to-end tests require a Windows machine; the included Python tests and static checks can run without Docker. This is an experimental tool, not a production-certified state engine.
- Existing (old) PostgreSQL volumes and credentials are **not migrated or used** by this new installation. The optional old-lab reset script is the only tool for stopping or deleting old state.
